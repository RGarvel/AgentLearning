# 行文规范（改写基线 v3）

> 本文件不是课程内容，是 `content/**/NN-*.md` 的改写规范。
> 构建只识别 `模块目录/NN-*.md`，本文件不会被编进课程。
>
> **v3 修订说明**：v1 把"易读"误解为"句子短、破折号少、表格多"；v2 立了"可操作性"，
> 但第 2 章连续两轮暴露新问题：① 配置只给零件、不给一条能跑通的完整路径（缺模型名、
> API 形态）；② 代码片段没说清存成什么文件、放哪、怎么运行；③ 场景铺得太多，读者
> 拿到的是"配置菜单"而非"装好的机器"。v3 补上这三条，并把"读者能否直接跑通"作为
> 唯一验收标准。

## 一、第一原则：读者能否直接跑通

**检验标准只有一条：一个新手拿着这一章，能不能一步步做成功、屏幕上能不能看到预期结果？**

"易读"不等于句子短、表格多。它等于——读者随时知道该做什么、代码能不能整段复制运行、
做完该看到什么、卡住了去哪查。

任何改写先过这一关，再谈行文。**指标（破折号数、段落长度）不是验收标准，跑通才是。**

## 二、十条硬规则（按优先级排序）

1. **前置条件写全**：凡涉及动手，先把"需要什么、什么版本、怎么装"交代清楚。不得假设读者
   已经装好了某个工具。装 Python、装 uv 这类步骤，给出可直接复制的命令和平台分支。
2. **给一条完整主线，不是配置菜单**：把"跑通"所需的**全部配置项**一次性列全（一个字段
   都不能漏），用一张对照表说明每项在每种场景下怎么设、漏了会报什么错。多种方案不要平铺
   成 A/B/C/D 让人挑，而是给一条默认路线走到底，其他方案降级为"可选微调"放主线之后。
3. **代码必须能整段运行**：一段示例代码就是一个能直接跑的完整脚本——含 import、`main`、
   `if __name__ == "__main__"`。若确实只能是片段，必须显式写"这是片段，不是完整脚本"，
   并说清它嵌到哪个文件的哪一步、依赖的前置变量从哪来。禁止出现 `agent.xxx` 这种
   `agent` 却没在前文定义的悬空片段。
4. **每个脚本交代三件事**：存成什么文件名、放在哪个目录（相对路径）、用什么命令运行。
   模板：``把它存成 `xxx.py`，放在 SDK 根目录 `openai-agents-python/` 下`` + 运行命令块 + 预期输出。
5. **每步给"做完标志"**：每个操作步骤后写明预期输出或验证命令，让读者能确认成功。
   整章有一个总验收点。
6. **命令可直接复制**：一个代码块只放一种方案、一个平台。禁止把"任选其一"的多个命令
   塞进同一个块。
7. **路径全程一致**：同一个目录在全章只能有一个名字。路径约定首次出现时讲清，并给
   "课程写法 ↔ 本机路径"对照表。
8. **先跑通、后补课**：操作类章节把"能跑起来"的主线放前面，背景知识和全景介绍放后面。
9. **一段一件事**：每段 2–4 句，单句尽量 ≤ 40 字。结论先行：二级小节第一句就是该节结论。
   长枚举（3 项以上带解释）改表格；纯步骤用有序列表。术语首现写「交接（handoff）」。
10. **不删技术要点**：原文每个坑、边界、注意都要保留，可以换说法，不能丢。

> 破折号（`——`）每节最多 1 处；代码块前说明"验证什么"，代码块后说明"预期结果"。

## 三、路径约定（v3 统一，必须遵守）

课程正文有两套路径，含义不同，不得混淆：

| 写法 | 含义 | 处理方式 |
| --- | --- | --- |
| `` `repo/xxx` `` | SDK 仓库内路径 | 构建自动链接到 GitHub `v0.25.0`，**必须保持 `repo/` 前缀**，点击跳转 |
| 裸的 `openai-agents-python/` | 本机 SDK 目录 | 不写 `repo/` 前缀，避免被当成源码引用；用于命令块和文件存放说明 |

**关键**：本机目录就叫 `openai-agents-python/`，不叫 `repo/`；也**不是** `repo/openai-agents-python/`
（后者是工作区视角，`repo/` 是课程的逻辑前缀）。每章首次涉及路径时给一次对照表：

| 课程里写的（可点击） | 你本机打开的文件 |
| --- | --- |
| `repo/src/agents/run.py` | `openai-agents-python/src/agents/run.py` |

规则：

- 相对路径一律相对本机 SDK 根目录，不写 `C:\Users\...` 这类绝对路径。
- 命令块首行标工作目录：`# 工作目录：openai-agents-python/（SDK 根目录）`。
- 读者若 clone 到别处，首次出现时说明"把命令里的 `openai-agents-python` 换成自己的路径即可，
  后文不再重复"。
- 改课程站本身（构建、跑测试）时用 `repo/AgentLearning/`，这与读者无关，一般不在课程正文出现。

## 四、章节骨架（二级标题集合与原文一致）

```text
# 第N章 标题
（开篇：上一章收尾 + 本章要解决的具体问题 + "按这章走完你会得到什么"）

## 学习目标        ← bullet list，构建抽取成卡片；写成可验证的操作目标
## 一、…           ← 正文小节；操作类的把主线前置，背景后置
## 常见坑与排查    ← 编号列表，每条含"症状 / 原因 / 修法"
## 动手练习        ← 编号列表，第一项必须能立刻做
## 本章小结        ← bullet list，6 条以内
## 延伸阅读        ← bullet list，末尾一句指向下一章
```

小节内部可用三级标题，但不新增与上述同级的标题。

## 五、自检清单（v3）

改完一章，逐条过：

**可操作性（优先，任一不过就是没改完）**
- [ ] 跑通所需的配置项已列全，每项说明"漏了报什么错"
- [ ] 给了一条完整默认主线，其他方案降级为可选，没有平铺成场景菜单
- [ ] 每段示例代码要么能整段运行，要么明确标注"片段"并说清嵌到哪
- [ ] 每个脚本都交代了：文件名 + 存放目录 + 运行命令 + 预期输出
- [ ] 前置工具/版本/安装命令写全；每个命令块只有一种方案、可直接复制
- [ ] 每个操作步骤都有"做完标志"或验证命令；整章有总验收点
- [ ] 路径全章一致，首次出现有对照表

**一致性**
- [ ] `wc -c` 不低于原文 90%（低于说明丢了内容）
- [ ] 原有代码块逐字未变（新增的工作目录/完整脚本块允许）
- [ ] 原有 `` `repo/...` `` 引用仍在，前缀未变
- [ ] 二级标题集合与原文一致
- [ ] `## 学习目标` 仍是 bullet list
