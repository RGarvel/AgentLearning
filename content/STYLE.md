# 行文规范（改写基线 v1）

> 本文件不是课程内容，是 `content/**/NN-*.md` 的改写规范。
> 构建只识别 `模块目录/NN-*.md`，本文件不会被编进课程。

## 一、改写目标

信息密度不变，认知负担下降。读者在手机上读一遍能抓住骨架，在电脑前读一遍能照着做。

**只改行文，不改事实。** 不动代码、不改 API 名称、不改版本号、不改技术结论。

## 二、七条硬规则

1. **一段一件事**：每段 2–4 句，单句尽量 ≤ 40 字。超长的复合句拆开。
2. **结论先行**：每个二级小节的第一句就是该节结论，加粗或无格式均可，但必须是一句能独立站住的话。
3. **削插入语**：破折号插入语（`——`）每节最多 1 处；原文用来补充说明的括号内容，改成独立短句，或放进表格。
4. **长枚举改表格**：3 项以上且每项都带解释的，优先用表格；纯步骤用有序列表，每项一行。
5. **术语首现加注**：首次出现写成「交接（handoff）」「护栏（guardrail）」，之后统一用中文。
6. **代码前后各一句**：代码块前说明「这段验证什么」，代码块后说明「预期结果是什么」。可断言的给预期输出。
7. **不删技术要点**：原文里的每个坑、每个边界、每个"注意"都要保留，可以换说法，不能丢。

## 三、目录约定（新增，必须遵守）

课程正文里的路径有两套，改写时不得混淆。

| 写法 | 含义 | 备注 |
| --- | --- | --- |
| `` `repo/xxx` `` | SDK 仓库内路径 | 构建时自动链接到 GitHub `v0.25.0`，**必须保持 `repo/` 前缀** |
| 命令块里的 `repo/openai-agents-python/` | 本地 SDK 根目录 | 仅出现在代码块中，构建不会把它当引用 |

**凡是让读者"动手"的地方**（装依赖、跑示例、改文件、开终端），必须先用一行注释标出工作目录：

```bash
# 工作目录：repo/openai-agents-python/（SDK 根目录）
cd repo/openai-agents-python
python examples/basic/hello_world.py
```

规则：

- 相对路径一律相对「工作目录」，不写 `C:\Users\...` 这类绝对路径。
- 两个工作目录，不要混：
  - **SDK 根目录** = `repo/openai-agents-python/`（跑示例、改源码、读 docs）
  - **课程站仓库** = `repo/AgentLearning/`（改课程本身、构建、跑测试）
- 读者若把仓库 clone 到别处（比如目录名就叫 `repo`），整段替换即可。第一次出现时说明这一点。
- 只在**首次出现**的位置说明映射关系，后面不必重复解释，但工作目录注释每次都要给。

## 四、章节骨架（不得增删二级标题）

顺序固定，标题文字不动：

```text
# 第N章 标题
（开篇 2–3 段：上一章收尾 + 本章要解决的问题 + 一句"读完你会知道什么"）

## 学习目标        ← 必须是 bullet list，构建会抽取成卡片
## 一、…           ← 正文小节，可多个
## 常见坑与排查    ← 编号列表，每条含"症状 / 原因 / 修法"三行
## 动手练习        ← 编号列表，第一项必须能立刻做
## 本章小结        ← bullet list，6 条以内
## 延伸阅读        ← bullet list，末尾一句指向下一章
```

小节内部可用三级标题，但不要新增与上述同级的其他标题。

## 五、自检清单

改完一章，逐条过：

- [ ] `wc -c` 结果不低于原文 90%（低于说明丢了内容）
- [ ] 所有代码块逐字未变
- [ ] 所有 `` `repo/...` `` 引用仍在，前缀未变
- [ ] 二级标题集合与原文完全一致
- [ ] `## 学习目标` 仍是 bullet list
- [ ] 每个动手步骤都有「工作目录」注释
- [ ] 全文搜索 `——`，每节不超过 1 处
