# 第0章 课程导读与学习地图

这套课程不是 API 手册的中文翻译。它是把 openai-agents-python 这个仓库（v0.25.0，1700+ 文件、其中 `src/agents` 约 12 万行 Python）**重新排序成一条能走通的路**：先建立"Agent 是一台什么机器"的心智模型，再逐个把零件装上去，最后用两个完整项目把它们焊死。

本章不涉及 API，但它决定了你后面 32 章的效率。

---

## 学习目标

- 说清这套课程的三层结构：**会用 → 会设计 → 会排查**，并知道自己现在在哪一层。
- 掌握"四步学习法"，能在一章 90 分钟内完成"读懂 → 跑通 → 改坏 → 修好"。
- 会用仓库的四个入口（`docs/`、`examples/`、`src/agents/`、`tests/`）自己查答案，而不是等我喂。
- 给自己排出一条现实的路线（3 天 / 2 周 / 源码深潜），并知道每一步的验收标准。

---

## 一、这套课程的三层结构

| 层级 | 对应模块 | 你要获得的能力 | 验收标准 |
| --- | --- | --- | --- |
| **会用** | 0、1、2、6 | 写出带工具、结构化输出、流式响应的 Agent | 能独立完成第 7 章练习，代码不报错 |
| **会设计** | 3、4、5、7 | 在 handoff / agent-as-tool / 单 Agent 之间做选择；设计记忆与安全边界 | 能给一个真实需求画出架构图并说明取舍 |
| **会排查** | 8、9、10 | 从 trace、items、异常类型定位问题；能读源码 | 拿到一个失败 run 能在 30 分钟内定位到环节 |

大多数人卡在"会用"和"会设计"之间，原因不是 API 不熟，而是**没有建立运行时的心智模型**。所以第 3-6 章（Agent 对象、运行循环、RunResult、上下文）是整套课的地基，不要跳过。

> 提示：如果你只有一天时间，读第 4 章 + 第 5 章 + 第 12 章。这三章解释了 80% 的"Agent 行为不符合预期"。

---

## 二、四步学习法（每章 60-90 分钟）

1. **读懂（20 分钟）**：先看"学习目标"和"本章小结"，再看正文。带着问题读，效率完全不同。
2. **跑通（30 分钟）**：把正文代码敲进文件跑一遍。**不要复制粘贴**——手敲会逼你注意每一个参数。
3. **改坏（15 分钟）**：故意改错一处（删掉 `max_turns`、把 `output_type` 换成错的类型、让工具抛异常），观察报错信息长什么样。这是建立"错误直觉"最快的方式。
4. **修好并记录（10 分钟）**：修回来，然后把"症状 → 原因 → 修法"写进自己的笔记。第 32 章的避坑清单就是这么来的。

> 注意：Agent 的行为是非确定性的。第 3 步"改坏"时，尽量改**结构性**的东西（参数、类型、顺序），而不是改 prompt 措辞——后者会让你误判。

## 三、仓库的四个入口（自己查答案的能力）

课程里所有结论都能在仓库里找到出处。学会用这四个入口，比记住任何 API 都重要：

| 入口 | 位置 | 什么时候用 | 怎么用 |
| --- | --- | --- | --- |
| **概念文档** | `repo/docs/*.md` | 想知道"这个功能设计意图是什么" | 先读对应页，注意 `!!! note` 块，那里通常是坑 |
| **可运行示例** | `repo/examples/` | 想知道"完整项目长什么样" | `customer_service`、`research_bot` 是两个最佳范本 |
| **源码** | `repo/src/agents/` | 想知道"到底怎么实现的" | 从 `__init__.py` 的导出找到类，再找调用点 |
| **测试** | `repo/tests/` | 想知道"边界情况怎么处理" | 测试是唯一不会骗人的规格说明 |

一个实用技巧：**遇到不确定的行为，先 grep 关键词，再看测试断言**。例如你想知道 `max_turns` 超了会怎样，搜 `MaxTurnsExceeded`，测试里会把异常信息、触发条件全写清楚。

## 五、给自己排一条路线

| 路线 | 顺序 | 时间 | 适合谁 |
| --- | --- | --- | --- |
| 速通 | 2→3→4→7→12→17→22→30 | 3 天，每天 4 小时 | 马上要落地一个 demo/POC |
| 系统 | 模块 0→7 顺序，模块 10 收尾 | 2 周，每天 2 小时 | 要长期做 Agent 产品 |
| 深潜 | 26→27→28→29，回读 1、4 模块 | 1 周 | 要改源码/做二次封装 |

无论哪条路线，**第 30 章的实战都必须动手做完**。它是整套课的"期末考"：如果它不卡壳，说明前 29 章真的吸收了。

## 六、常见放弃点（提前打预防针）

1. **第 4 章看不懂运行循环**：正常。先记住"模型 → 工具 → 回填 → 再问模型"这个四拍节奏，第 28 章会带你逐行读源码，到时候会豁然开朗。
2. **第 9 章 MCP 配不通**：90% 是子进程启动参数或环境变量问题，不是 SDK 问题。先用官方的 filesystem server 跑通最小例子。
3. **第 13 章沙箱跑不起来**：沙箱依赖 Docker/远端服务，本地环境不满足很常见。**可以先跳过**，不影响后面章节。
4. **第 25/26 章语音没设备**：没有麦克风也能读——把 pipeline 当成"另一个输入输出适配层"理解即可。
5. **学到第 18 章开始混乱**：因为"记忆"这个词在 SDK 里至少有三个不同东西（`to_input_list`、`session`、`previous_response_id`）。第 18 章有一张决策表，混乱时回去看那张表。

## 动手练习

1. **画一张自己的地图**：用纸画出"输入 → Agent → 工具 → 输出"的流程，标出你目前不确定的环节（至少 3 个）。学完后回来对照，看是否都能填上。
2. **找一次答案**：不看课程，只用 `repo/docs` 和 `repo/tests`，回答"当 output_type 校验失败时 SDK 抛什么异常"。把查找路径记下来。
3. **改进阶目标**：从第 30/31 章两个项目里挑一个，写下你希望学完后能独立实现的版本（一两句话即可），贴在桌前。

## 本章小结

- 课程分三层：会用（0/1/2/6）、会设计（3/4/5/7）、会排查（8/9/10）。
- 每章用"四步法"：读懂 → 跑通 → 改坏 → 修好并记录。
- 仓库四个入口：`docs`（意图）、`examples`（范式）、`src`（实现）、`tests`（规格）。
- 模块 0 和 1 是地基，不能跳；模块 8/9 是选修。
- 所有路线最后都要落在第 30 章的实战上。
- 遇到卡点先查 tests，它比任何教程都诚实。
