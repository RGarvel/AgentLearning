# 第2章 仓库全景与环境搭建

上一章我们把 Agent 拆成了"模型 + 指令 + 工具 + 循环"四个部件。这一章解决一个非常具体的问题：面对一个 1700 多个文件、`src/agents` 约 12 万行 Python 的仓库，你的眼睛该先落在哪里？

环境也要一次性配好。配环境不是体力活：把 Python 版本、依赖形态、API Key 的解析时机搞对，能省掉你后面两周里 80% 的"莫名其妙"。

---

## 学习目标

- 能说清仓库五个区域（`src/agents`、`docs`、`examples`、`tests`、`integration_tests`）各自的职责，并在遇到问题时知道先查哪个。
- 能判断 `src/agents` 里哪些是"门面"、哪些是"内部实现"，不会一上来就在 `run_internal/` 里迷路。
- 能装好 0.25.0 并跑通 `hello_world`，且知道版本约束（`requires-python`、`openai>=3`）从哪来。
- 能用 `run_demo_loop` 做交互式验证，而不是每次改代码都重发一条消息。
- 能独立排查四类环境问题：Python 版本、解释器选错、网络/代理、uv 与虚拟环境混用。

## 一、仓库的五个区域

仓库里真正需要你认识的只有五个区域。先记住它们的分工，遇到问题时就知道该往哪里查。

| 区域 | 是什么 | 什么时候查它 | 备注 |
| --- | --- | --- | --- |
| `repo/src/agents/` | SDK 源码本体 | 想知道"到底怎么实现的""这个参数在哪被用" | 唯一权威，文档与源码冲突时以它为准 |
| `repo/docs/` | 官方英文文档 | 想知道"设计意图是什么" | 注意 `!!! note` 块；`docs/zh`、`docs/ja`、`docs/ko` 是自动生成的译文，不要编辑 |
| `repo/examples/` | 17 个可运行示例目录 | 想知道"完整项目长什么样" | `customer_service`、`research_bot` 是最佳范本 |
| `repo/tests/` | 单元测试 | 想知道"边界情况怎么处理" | 测试是唯一不会骗人的规格说明 |
| `repo/integration_tests/` | 集成测试 | 想验证真实网络/容器/供应商 | 需要凭证或 Docker，普通开发不用跑 |

`src/agents/` 再往下一层，可以按"你多久会打开它"分成三类。

| 分类 | 文件/目录 | 用途 |
| --- | --- | --- |
| 门面层（天天看） | `agent.py`、`run.py`、`result.py`、`items.py`、`tool.py`、`run_context.py`、`run_config.py` | 第 3-6 章的核心；这几个类构成了 SDK 的全部骨架 |
| 能力层（按需看） | `handoffs/`、`guardrail.py`、`tool_guardrails.py`、`memory/`、`mcp/`、`models/`、`tracing/`、`stream_events.py`、`lifecycle.py`、`retry.py` | 每个子目录对应课程的一个模块 |
| 运行时内部（出问题才看） | `run_internal/`、`_tool_identity.py`、`_tool_invocation.py`、`_config.py`、`function_schema.py`、`strict_schema.py` | `run_internal/` 是第 28 章的主战场，日常不要从这里读起 |

还有几类"非代码但极有用"的文件，值得先认个脸。

| 文件 | 为什么值得看 |
| --- | --- |
| `repo/AGENTS.md`、`repo/CLAUDE.md` | 仓库给 AI 编码助手立的工程规矩。想给这个仓库提 PR 之前，先读它。 |
| `repo/Makefile` | 所有官方检查命令的入口（`make sync`、`make tests`、`make typecheck`）。 |
| `repo/pyproject.toml` | 版本、依赖、可选 extras 的唯一真相。 |
| `repo/tests/README.md` | 测试怎么跑、什么时候必须用 `ScriptedModel`。 |

### examples/ 的 17 个目录，按用途分四组

初学者最容易犯的错，是把 `examples/` 当目录浏览一遍。它们其实有明确的功能分层。

| 组 | 目录 | 你会在这里看到什么 |
| --- | --- | --- |
| 基础动作 | `basic/` | `hello_world`、`tools`、`stream_text`/`stream_items`、`previous_response_id`、`usage_tracking`、`tool_guardrails`、`retry`、`prompt_template` |
| 编排范式 | `agent_patterns/`、`handoffs/` | `routing`（分诊）、`agents_as_tools`（manager 模式）、`parallelization`、`deterministic`、`llm_as_a_judge`、`input_guardrails`/`output_guardrails`、`human_in_the_loop`；`message_filter` 展示交接时如何裁剪历史 |
| 完整项目 | `customer_service/`、`research_bot/`、`financial_research_agent/` | 多 Agent + 工具 + 结构化输出的真实骨架，第 30、31 章会精读前两个 |
| 专项能力 | `mcp/`、`hosted_mcp/`、`tools/`、`memory/`、`model_providers/`、`realtime/`、`voice/`、`sandbox/`、`decisions/`、`reasoning_content/`、`live/` | MCP 接入、托管工具（shell/apply_patch/web_search/code_interpreter）、会话后端、供应商适配、语音与实时、沙盒工作区、模型路由 |

根目录还有两个工具脚本，知道就行，不必细读。`auto_mode.py` 在 `EXAMPLES_INTERACTIVE_MODE=auto` 时给示例提供确定性的输入与确认；`run_examples.py` 批量发现并运行示例，把日志写到 `.tmp/examples-start-logs`。

> 提示：不要试图一次跑完 `examples/`。顺序应是 `basic` → `agent_patterns` → 挑一个真实项目跟读。沙盒（`sandbox/`）与语音（`voice/`、`realtime/`）依赖额外服务或设备，读不通可以先跳过。

`docs/` 本身也分两层。根目录是按主题组织的指南（`agents.md`、`tools.md`、`running_agents.md`、`results.md`、`context.md` 等）；子目录按子栈切分（`models/`、`sessions/`、`realtime/`、`voice/`、`sandbox/`、`tracing/`、`testing/`）；`ref/` 下则是自动生成的 API 参考。

查资料时先确认自己在"概念层"还是"参考层"：前者解释为什么这样设计，后者只给签名。

`tests/` 的组织方式同理。目录名基本对应源码模块（`models/`、`memory/`、`sandbox/`、`realtime/`、`tracing/`、`voice/`、`mcp/`）。所以"我想知道某个模块的边界行为"最省力的路径，就是直接进同名测试目录。

> **路径约定**：课程正文里的 `repo/xxx` 一律指 SDK 仓库内的相对路径，构建时会自动链接到 GitHub 的 `v0.25.0`。
>
> 本地把这套源码放在 `repo/openai-agents-python/` 下。所以正文写 `repo/src/agents/run.py`，你打开的文件是 `repo/openai-agents-python/src/agents/run.py`。
>
> 如果你 clone 到了别处（比如目录名就叫 `repo`），把命令块里的 `cd repo/openai-agents-python` 换成自己的路径即可，后文不再重复。

## 二、安装：pip、uv 与版本约束

0.25.0 的元数据全部写在 `repo/pyproject.toml` 里，装之前先对一遍三条硬信息。

```toml
name = "openai-agents"
version = "0.25.0"
requires-python = ">=3.10"
```

运行时依赖里有两个值得记住的：

- `openai>=3.0.0,<4`：0.25 用的是 openai v3，**自定义 `http_client` 必须用 httpx2 类型**（见 `repo/docs/config.md`），老的 `httpx` 客户端对象不再直接适配。
- `pydantic>=2.12.2,<3`：所有 `output_type`、`ModelSettings` 的校验都建立在它上面。

三种装法，按场景选。若你把仓库 clone 到了别处（比如目录名就叫 `repo`），把下文命令标注的 SDK 根目录换成本机实际路径即可，后文不再重复。

```bash
# 工作目录：任选；第 2 种会 clone 出 repo/，第 3 种在 SDK 根目录执行
# 1) 只想用，不读源码（最小）
pip install openai-agents

# 2) 想读源码 / 想改示例（推荐：可编辑安装）
git clone https://github.com/openai/openai-agents-python.git repo
cd repo
uv venv
uv pip install -e .

# 3) 想跑仓库自带测试与类型检查（最全）
uv sync --all-extras --all-packages --group dev   # 等价于 make sync
```

第 2 种装法里的 `repo` 就是本书所说的 SDK 根目录。`cd repo` 之后，你就在 SDK 根目录里了。

安装形态还会决定你后面几章能不能跑通。0.25 把重依赖都收进了 extras：语音流水线要 `voice`（numpy、websockets），图结构可视化要 `viz`（graphviz），LiteLLM 供应商要 `litellm`，数据库会话要 `sqlalchemy`、`redis`、`mongodb`，加密会话要 `encrypt`。

默认安装只带"文本 Agent"所需的最小集合。这是刻意设计：它保证 `import agents` 不会因为缺少可选依赖而失败。

| 你的目标 | 安装方式 |
| --- | --- |
| 只想跑文本 Agent | `pip install openai-agents` |
| 跟完整套课程（含语音、可视化、多种会话后端） | `uv sync --all-extras --all-packages --group dev` |
| 生产镜像要最小 | 默认安装，按需加单个 extra，如 `pip install "openai-agents[voice]"` |

装完必须验证一句，否则后面所有报错你都分不清是代码问题还是环境问题。

```bash
# 工作目录：repo/openai-agents-python/（SDK 根目录）
cd repo/openai-agents-python
python -c "import agents, sys; print(sys.version); print(agents.__version__)"
```

预期输出里应包含 `3.10` 以上版本号和 `0.25.0`。如果打印的是另一个版本，说明你用的解释器不是刚装的那个。这在装了多个 Python 的 Windows 机器上极其常见。

> 注意：`uv venv` 只创建虚拟环境，不会自动"激活"它。后面每条命令要么先 `.venv\Scripts\activate`（Windows）/`source .venv/bin/activate`（macOS、Linux），要么统一用 `uv run python ...` 前缀。

## 三、API Key：三种设置方式

SDK 默认从 `OPENAI_API_KEY` 环境变量取 key，并且是**惰性解析**：直到第一次真正创建 OpenAI 客户端时才读（`repo/docs/config.md`）。

这意味着"程序启动时设 key"和"import 时设 key"都能生效，但"模型调用发生之后才设"一定失败。

```bash
# 工作目录：任意（环境变量与当前目录无关）
# macOS / Linux
export OPENAI_API_KEY=sk-...

# Windows PowerShell
$env:OPENAI_API_KEY = "sk-..."

# Windows CMD
set "OPENAI_API_KEY=sk-..."
```

如果 key 不在环境变量里，可以在应用启动处显式设置（适合从密钥管理服务读取）：

```python
from agents import set_default_openai_key

set_default_openai_key("sk-...")  # 同时会用于 tracing 导出
```

需要换端点（自建网关、兼容代理）时，用环境变量或自定义客户端：

```bash
# 工作目录：任意（环境变量与当前目录无关）
OPENAI_BASE_URL="https://your-gateway.example.com/v1"
OPENAI_DEFAULT_MODEL="gpt-5-nano"   # 覆盖默认模型 gpt-5.6-luna
```

关于 `.env` 有一个必须说清的事实：**SDK 不会自动加载 `.env`**。仓库的 `examples/` 里也没有引入 `python-dotenv`。想要 `.env` 体验，有两个干净做法。

```bash
# 工作目录：repo/openai-agents-python/（SDK 根目录）
cd repo/openai-agents-python
# 做法一：让 uv 帮你注入环境变量（不装额外依赖）
uv run --env-file .env python examples/basic/hello_world.py
```

```python
# 做法二：在自己的入口脚本里加载（需要 pip install python-dotenv）
from dotenv import load_dotenv

load_dotenv()  # 必须在任何模型调用之前

from agents import Agent, Runner  # noqa: E402
```

> 注意：不要把 key 写进 `instructions`、context 或任何会被序列化的 `RunState` 字段。第 16 章会讲状态持久化，而 `RunContextWrapper.context` 里的内容会随状态一起被写出。

## 四、三行跑通 hello_world

仓库里最小可跑的脚本是 `repo/examples/basic/hello_world.py`，核心就三行。

```python
import asyncio

from agents import Agent, Runner


async def main() -> None:
    agent = Agent(name="Assistant", instructions="You only respond in haikus.")
    result = await Runner.run(agent, "Tell me about recursion in programming.")
    print(result.final_output)


if __name__ == "__main__":
    asyncio.run(main())
```

这段要验证的是"环境 + key + 网络"三件事是否同时通了。运行它只需要一条命令。

```bash
# 工作目录：repo/openai-agents-python/（SDK 根目录）
cd repo/openai-agents-python
python examples/basic/hello_world.py
```

预期输出是一段三行俳句。内容每次不同，但形状固定：

```text
Function calls itself,
Looping in smaller pieces,
Endless by design.
```

三条关键行值得单独说：

| 代码行 | 它此刻做了什么 |
| --- | --- |
| `Agent(...)` | 纯声明，不发请求。它此刻只是四个部件里的两个（指令 + 默认模型）。 |
| `Runner.run(agent, "...")` | 这里才发生模型调用、轮次计数、停止判定（第 4 章）。 |
| `print(result.final_output)` | `final_output` 的类型由 Agent 的 `output_type` 决定，默认 `str`（第 5 章）。 |

## 五、交互式 REPL：run_demo_loop

改一次代码发一条消息太慢，SDK 自带一个终端 REPL。

```python
import asyncio

from agents import Agent, run_demo_loop


async def main() -> None:
    agent = Agent(name="Assistant", instructions="You are a helpful assistant.")
    await run_demo_loop(agent)


if __name__ == "__main__":
    asyncio.run(main())
```

这段脚本能验证的是多轮对话行为：你输入一句、它回一句，历史一直留着。

它的行为（`repo/docs/repl.md`）：循环读入用户输入、**保留整段对话历史**、默认以流式方式打印模型输出；输入 `quit`、`exit` 或按 `Ctrl-D` 退出。

它适合做三件事：验证指令措辞、观察多轮记忆是否符合预期、快速试工具。

它不适合做两件事：压测（没有并发控制）和回归（输出不确定，无法断言）。后者请用第 23 章的测试替身。

## 六、建议的阅读与实验顺序

不要从 `run_internal/` 开始。这条顺序和课程主线一致，每一步都有"看得见的产出"。

| 阶段 | 读什么 | 跑什么 | 验收 |
| --- | --- | --- | --- |
| 1. 骨架 | 第 3-6 章 + `agent.py`/`run.py` | `examples/basic/hello_world.py`、`tools.py` | 能解释 `final_output` 从哪来 |
| 2. 工具 | 第 7-8 章 + `tool.py` | `examples/basic/tool_guardrails.py` | 能写出带 Pydantic 返回值的工具 |
| 3. 编排 | 第 11-12 章 + `handoffs/` | `examples/agent_patterns/` | 能说清 handoff 与 agent-as-tool 的区别 |
| 4. 安全 | 第 14-16 章 + `guardrail.py` | `examples/basic/tool_guardrails.py` | 能设计三层防护 |
| 5. 状态 | 第 17-18 章 + `memory/` | `examples/memory/` | 能选对四种记忆策略 |
| 6. 观测 | 第 22-23 章 + `tracing/` | `examples/basic/usage_tracking.py` | 能读懂一次 trace 的层级 |

还有一层常被误解的事：**读源码不是学习方式，而是验证手段**。先用示例建立行为预期，等你心里冒出一句"它凭什么这样"时，再去源码里找那一段。

带着问题读十行，胜过无目的地读一千行。这也是本课程每章都给出"源码位置"却不要求你通读的原因。

一个反直觉但有效的建议：**先读 `examples/`，再读 `docs/`，最后读源码**。示例给你"能跑的形状"，文档给你"为什么这样设计"，源码在你产生"真的是这样吗"的疑问时才最有价值。

## 七、跟进上游版本（让知识不过期）

本课程锁定 **0.25.0**（2026-11-17 发布）。上游迭代很快，判断"要不要更新你的知识"只需要三步。

1. **看版本与变更**：`repo/CHANGELOG.md` 顶部的版本号与 Features / Bug Fixes 列表，十分钟能读完。
2. **看文档有没有变**：`docs/` 变了通常意味着语义变了；只有 `src/` 变、文档没动，多半是内部重构。
3. **看公开 API 契约**：`repo/tests/fixtures/released_api_contract.json` 逐项记录了每个公开类/函数的参数与默认值。对比两版这个文件，就是最权威的"公开 API 到底变没变"。

这三步也是本课程自己更新时用的方法，0.24 → 0.25 的具体差异与课程改动，见根目录 `版本与更新记录.md`。

## 常见坑与排查

1. **症状**：`pip install openai-agents` 成功，运行却 `ModuleNotFoundError: No module named 'agents'`。
   **原因**：装到了另一个解释器（系统 Python vs 虚拟环境），或在错误的终端会话里。
   **修法**：`python -c "import sys; print(sys.executable)"` 看清解释器路径；统一用 `uv run python ...`。

2. **症状**：Python 3.9 下 import 就报语法/类型错误。
   **原因**：`requires-python = ">=3.10"`，源码大量使用 `X | None` 与 `kw_only` dataclass 字段。
   **修法**：升级到 3.11 或 3.12（0.25 的分类器覆盖到 3.14，但 3.11/3.12 生态最稳）。

3. **症状**：模型调用超时、`APIConnectionError`，但浏览器能打开网页。
   **原因**：企业代理没有传给 Python 进程，或 `OPENAI_BASE_URL` 指向了不可达网关。
   **修法**：设 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量；确认 `OPENAI_BASE_URL` 以 `/v1` 结尾；离线开发时用 `set_tracing_disabled(True)` 至少关掉追踪导出，避免噪音。

4. **症状**：只看到一条 warning：`OPENAI_API_KEY is not set, skipping trace export`。
   **原因**：追踪导出需要 key（默认与模型调用同一把）。这只影响 trace 上传，不影响运行。
   **修法**：要么补 key，要么 `set_tracing_disabled(True)`，要么用 `set_tracing_export_api_key(...)` 单独指定。

5. **症状**：自己传 `http_client=` 给 `AsyncOpenAI` 后，报类型不匹配或连接异常。
   **原因**：0.25 依赖 `openai>=3`，默认走 HTTPX2；旧教程里的 `httpx` 客户端不再适用。
   **修法**：按 `repo/docs/config.md` 用 `httpx2` 与 `DefaultAsyncHttpx2Client` 构造。

6. **症状**：Windows 上 `.venv\Scripts\activate` 提示"禁止运行脚本"。
   **原因**：PowerShell 执行策略限制，不是 SDK 问题。
   **修法**：只对当前会话放宽（`Set-ExecutionPolicy -Scope Process RemoteSigned`），或干脆全程用 `uv run`。

## 动手练习

1. **验证环境**：打印 `sys.version`、`sys.executable`、`agents.__version__` 三个值，写进你的笔记。以后任何"跑不起来"先回看这三行。
2. **跑通 REPL**：把上面的 REPL 脚本存成一个文件，在 SDK 根目录下运行。连问三个相关问题（例如"我叫小林"→"我叫什么"→"请用一句话复述"），确认它记住了前文；然后中途输入 `exit` 退出。
3. **改仓库示例**：打开 `repo/examples/basic/tools.py`，把 `get_weather` 的返回类型从 `Weather` 改成 `str`，再改回来。对比两次运行中 `result.final_output` 与模型行为的变化，并思考：返回值类型到底影响了什么？（这是第 7 章的入口问题。）

## 本章小结

- 五个区域分工：`src` 是权威，`docs` 是意图，`examples` 是范式，`tests` 是规格，`integration_tests` 是真实环境验证。
- `src/agents/` 分三层：门面（`agent/run/result/items`）、能力（`handoffs/memory/mcp/tracing`）、内部（`run_internal/`）；日常只读前两层。
- 版本硬约束：`requires-python>=3.10`、`openai>=3`、`pydantic>=2.12`；0.25 的 HTTP 客户端要用 httpx2。
- API Key 惰性解析自 `OPENAI_API_KEY`；SDK 不自动读 `.env`，可用 `uv run --env-file` 或 `python-dotenv`。
- `hello_world` 验证环境，`run_demo_loop` 验证行为；两者都不能当回归测试用。
- 阅读顺序：示例 → 文档 → 源码；源码从门面层进，不从 `run_internal/` 进。
