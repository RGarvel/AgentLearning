# 第2章 从零搭建运行环境

这一章只做一件事：带你从一台什么都没装的机器，一路跑到 `hello_world` 输出一首俳句。

顺序是先跑通、再补课。仓库结构和背景知识放在后半章——等你屏幕上真的跑出了结果，再回头看它们才有意义。

按这一章走完，你会得到三样东西：一个能跑的 Python 环境、一份放在本机可随时查阅的 SDK 源码、一条验证环境是否正常的命令。

---

## 学习目标

- 在本机装好 Python 3.12 与 uv，并用一条命令确认版本正确。
- 把 SDK 源码 clone 到本机的 `openai-agents-python/`，并说清它和课程里 `repo/xxx` 写法的对应关系。
- 用可编辑安装（`uv pip install -e .`）装好 0.25.0，跑通 `hello_world`。
- 按官方或网关场景，一次配齐 key、base URL、模型名和 API 形态四项。
- 知道 SDK 惰性解析配置，且不会自动加载 `.env`。
- 用一条命令打印解释器路径和版本号，能凭它自查环境类故障。

## 二、先说清一个路径约定（不看会走错）

课程正文里会反复出现 `repo/src/agents/run.py` 这样的写法。这里最容易把人绕晕，先一次性讲清楚。

`repo/` 是**课程的逻辑前缀**，意思是"SDK 仓库里的路径"。点击它会自动跳到 GitHub 上 v0.25.0 的对应文件。它**不要求你真的建一个叫 `repo` 的目录**。

本机上，我们把源码 clone 成 `openai-agents-python/`。两者对照如下：

| 课程里写的（可点击） | 你本机打开的文件 |
| --- | --- |
| `repo/src/agents/run.py` | `openai-agents-python/src/agents/run.py` |
| `repo/examples/basic/hello_world.py` | `openai-agents-python/examples/basic/hello_world.py` |
| `repo/docs/quickstart.md` | `openai-agents-python/docs/quickstart.md` |

一句话记住：**本机目录叫 `openai-agents-python`，不叫 `repo`。** 下面所有命令都用这个目录名，前后一致。

如果你的源码放在别处，把命令里的 `openai-agents-python` 换成自己的路径即可，后文不再重复。

## 三、第 1 步：装 Python 3.12

0.25.0 要求 Python 3.10 以上（`requires-python = ">=3.10"`）。用 3.9 会在 import 阶段就报语法错。

推荐装 3.12：3.11 和 3.12 的第三方库生态最稳，而 3.9 已不满足要求、3.13/3.14 的部分依赖还没跟上。

按你的系统选一条命令：

```bash
# Windows（用 winget）
winget install Python.Python.3.12

# macOS（用 Homebrew）
brew install python@3.12

# Ubuntu / Debian
sudo apt install python3.12 python3.12-venv
```

装完立刻验证。这条命令在后面还会反复用到，建议记下来。

```bash
python --version
```

预期输出形如 `Python 3.12.x`。如果提示"不是内部或外部命令"，说明 Python 没进 PATH——Windows 上重装时勾选 Add Python to PATH，或关闭重开终端再试。

## 四、第 2 步：装 uv

uv 是一个 Python 包与虚拟环境管理器，比 pip 快很多，还能锁住依赖版本。这门课全程用它装依赖。

按你的系统选一条：

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows（PowerShell）
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

验证：

```bash
uv --version
```

能看到版本号就装好了。装完需要**关闭终端重开一次**，否则 `uv` 可能还不在 PATH 里。

> 如果你坚持用 pip，也可以——但后面 `uv sync`、`uv run` 那些命令就要自己换成对应的 pip / python 写法。为了跟课程一致，建议就用 uv。

---

## 五、第 3 步：拿源码，装依赖

现在把 SDK 源码下载到本机。这条命令会在当前目录下创建 `openai-agents-python/`：

```bash
git clone https://github.com/openai/openai-agents-python.git
cd openai-agents-python
```

`cd` 之后，你就站在 **SDK 根目录**了。后面所有示例命令都从这里发起。用一条命令确认位置没错：

```bash
ls pyproject.toml
```

能看到 `pyproject.toml` 就对了。这个文件是版本和依赖的唯一真相：`version = "0.25.0"`、`requires-python = ">=3.10"`，还有 `openai>=3.0.0,<4`、`pydantic>=2.12.2,<3` 两条运行时约束。

接下来建虚拟环境并做**可编辑安装**——这样你改了源码里的示例，立刻就能跑，不用重装：

```bash
uv venv
uv pip install -e .
```

第一条创建 `.venv/`，第二条把 SDK 以可编辑模式装进去。这两条命令合起来，就是课程里说的"推荐装法"。

装完必须验证，否则后面所有报错你都分不清是代码问题还是环境问题：

```bash
python -c "import sys, agents; print(sys.version); print(sys.executable); print(agents.__version__)"
```

预期看到三行：Python 版本（3.10 以上）、解释器路径（指向 `.venv`）、`0.25.0`。

> **Windows 常见坑**：`uv venv` 只创建虚拟环境，不会自动激活它。你有两种选择——要么每条命令前先激活（`.venv\Scripts\activate`，PowerShell 若报"禁止运行脚本"先执行 `Set-ExecutionPolicy -Scope Process RemoteSigned`），要么统一用 `uv run python ...` 前缀，省去激活这一步。课程命令采用前一种写法，两种等价。

### 要不要装全部可选依赖？

默认安装只带"文本 Agent"的最小集合，这是刻意设计——保证 `import agents` 不会因缺可选依赖而失败。语音、可视化、多种会话后端都放在 extras 里，按需装：

| 你的目标 | 安装命令 |
| --- | --- |
| 先跟课程主线（文本 Agent） | `uv pip install -e .`（刚做的，够了） |
| 要跑语音 / 可视化 / 数据库会话等全部示例 | `uv sync --all-extras --all-packages --group dev` |
| 生产环境要最小镜像 | 默认安装，再单独加需要的 extra，如 `uv pip install -e ".[voice]"` |

建议现在先用第一种，读到语音、会话那几章再回来补。

## 六、第 4 步：一次配齐运行时配置

这一步只有一个目标：让下一节的 `hello_world` 跑出结果。

SDK 要跑起来，需要知道四件事。先把这张表看清，再按你的情况走对应路线：

| 配置项 | 决定什么 | 官方 OpenAI | 兼容网关 / 自建代理 |
| --- | --- | --- | --- |
| API Key | 凭据 | 必须有，官方签发 | 必须有，网关签发 |
| base URL | 请求发去哪 | 不用设，默认 `api.openai.com` | **必须设**，指向网关 |
| 模型名 | 调用哪个模型 | 不用设，默认 `gpt-5.6-luna` | **必须设**，换成网关真正支持的模型 |
| API 形态 | 用哪种协议 | 不用设，默认 Responses API | **多数要切**成 Chat Completions |

一句话：**官方场景只设一把 key；网关场景四项都要配齐。** 漏掉后两项是最常见的"key 和地址都对、就是跑不通"的原因——报错信息通常只说模型不存在或接口不支持，不会提示你少了哪项配置。

> 一条贯穿全节的规则：SDK 惰性解析配置（`repo/docs/config.md`）。它直到第一次真正创建客户端时才读这些值。所以下面所有设置都必须在**第一次模型调用之前**完成，之后设一律不生效。

### 路线一：官方 OpenAI（只设 key）

去 <https://platform.openai.com/api-keys> 创建一把 key，复制备用。按你的系统选**一条**命令，把 `sk-...` 换成自己的 key：

```bash
# macOS / Linux —— 当前终端会话
export OPENAI_API_KEY=sk-...
```

```powershell
# Windows PowerShell —— 当前终端会话
$env:OPENAI_API_KEY = "sk-..."
```

```cmd
:: Windows CMD —— 当前终端会话
set "OPENAI_API_KEY=sk-..."
```

验证 key 已就位。这条只显示前四位，不泄露完整密钥：

```bash
# macOS / Linux
echo ${OPENAI_API_KEY:0:4}
```

```powershell
# Windows PowerShell
$env:OPENAI_API_KEY.Substring(0,4)
```

看到 `sk-` 就对了。上面的设置只对当前终端窗口有效；关掉重开要重新设。想长期生效：

- Windows：系统属性 → 高级 → 环境变量 → 用户变量里新建 `OPENAI_API_KEY`
- macOS / Linux：把 `export OPENAI_API_KEY=sk-...` 追加到 `~/.zshrc` 或 `~/.bashrc`，再 `source` 一次

**模型名和 API 形态都不用动。** SDK 默认用 `gpt-5.6-luna` 走 Responses API，官方场景直接可用。现在可以跳到下一节跑 `hello_world` 了。

> 安全提醒：不要把 key 写进 `instructions`、context 或任何会被序列化的 `RunState` 字段。第 16 章讲状态持久化时你会看到，`RunContextWrapper.context` 里的内容会随状态一起被写出。

### 路线二：兼容网关（四项一次配齐）

这是国内开发最高频的场景。下面这份脚本把四项配置全放在一起，**改掉四个占位符就能跑**。把它存成 `gateway_hello.py`，放在 SDK 根目录：

```python
from agents import (
    Agent,
    Runner,
    set_default_openai_api,
    set_default_openai_client,
    set_tracing_disabled,
)
from openai import AsyncOpenAI

# 1. 端点 + key：都交给 client
client = AsyncOpenAI(
    base_url="https://your-gateway.example.com/v1",  # ← 改成你的网关地址，通常带 /v1
    api_key="你的网关key",                            # ← 改成网关签发的 key
)
set_default_openai_client(client)

# 2. API 形态：多数兼容网关只支持 Chat Completions
set_default_openai_api("chat_completions")

# 3. 追踪：网关 key 通常不能用于 OpenAI 追踪，直接关掉最省心
set_tracing_disabled(True)


async def main():
    # 4. 模型名：必须换成你的网关真正支持的模型
    agent = Agent(
        name="Assistant",
        instructions="You only respond in haikus.",
        model="你的网关模型名",  # ← 例如 gpt-4o-mini，别留默认
    )
    result = await Runner.run(agent, "Tell me about recursion in programming.")
    print(result.final_output)


if __name__ == "__main__":
    import asyncio

    asyncio.run(main())
```

运行它：

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
python gateway_hello.py
```

四个占位符里，最容易出错的是**模型名**。去网关的控制台看它实际提供哪些模型 ID，照抄那个字符串。很多人以为设了 base URL 就能沿用默认的 `gpt-5.6-luna`——网关没这个模型，会直接返回 `model not found`。

#### 这四行为什么都不能省

| 配置 | 省掉会发生什么 | 判断方法 |
| --- | --- | --- |
| `base_url` 写进 client | 请求发到 `api.openai.com`，报 `APIConnectionError` 或 401 | 确认地址带 `/v1` 且网关可达 |
| `api_key` 写进 client | 找不到凭据，直接报鉴权失败 | 只设环境变量不设 client 的 key 也会失败，见下文 |
| `set_default_openai_api("chat_completions")` | 默认发 Responses API 请求，网关返回 404 或"接口不支持" | 网关文档若只提 `/chat/completions`，就必须切 |
| `model="..."` | 沿用 `gpt-5.6-luna`，网关报 model not found | 用网关控制台里的模型 ID 原样填写 |

关于 key 有一处必须讲清：**一旦传了自定义 client，SDK 就完全用它，不再读 `OPENAI_API_KEY` 环境变量。** 所以 key 必须传进 `AsyncOpenAI(api_key=...)`。只设了环境变量、却传了一个没带 key 的 client，会因找不到凭据而失败。这条规则反过来也成立——用了 client 之后，环境变量里的 key 和 base URL 都被忽略，不要两边都设。

`use_for_tracing` 还有个默认值问题：`set_default_openai_client(client)` 默认把 client 的 key 同时设为追踪 key。网关 key 一般不能拿去调 OpenAI 追踪接口，所以上面直接用 `set_tracing_disabled(True)` 关掉。想保留追踪、又要用不同 key，见后面的「追踪单独配置」。

#### 如果你的网关支持 Responses API

少数网关完整实现了 Responses 接口。那种情况下可以删掉 `set_default_openai_api("chat_completions")`，但仍要设模型名、base URL 和 key。若还要用 websocket 传输，另外设端点（协议是 `wss://`）：

```bash
export OPENAI_WEBSOCKET_BASE_URL="wss://your-gateway.example.com/v1"
```

主线用不到这项，遇到再回来查。

### 等价的环境变量写法（可选）

路线二用的是"client 一条路走到底"。如果你更习惯不改代码，也可以把端点、key、模型名都放进环境变量，只对 API 形态和追踪保留两行代码：

```bash
# macOS / Linux
export OPENAI_BASE_URL="https://your-gateway.example.com/v1"  # 末尾带 /v1
export OPENAI_API_KEY="你的网关key"
export OPENAI_DEFAULT_MODEL="gpt-4o-mini"                       # 换成网关支持的模型
```

```powershell
# Windows PowerShell
$env:OPENAI_BASE_URL = "https://your-gateway.example.com/v1"
$env:OPENAI_API_KEY = "你的网关key"
$env:OPENAI_DEFAULT_MODEL = "gpt-4o-mini"
```

然后在入口脚本里保留两行（这两项没有环境变量写法）：

```python
from agents import set_default_openai_api, set_tracing_disabled

set_default_openai_api("chat_completions")
set_tracing_disabled(True)
```

这两条路线不要同时用。判断规则只有一句：**传了自定义 client，client 就是唯一真相；没传 client，SDK 才分别读环境变量和设置函数，再把它们组合起来。**

### 想用 `.env` 文件

SDK 不会自动加载 `.env`，仓库示例里也没引入 `python-dotenv`。两个干净做法：

**做法一：让 uv 帮你注入（不装额外依赖）**

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
uv run --env-file .env python examples/basic/hello_world.py
```

`.env` 里放三项，一次写全：

```dotenv
OPENAI_API_KEY=sk-...                                   # 或网关 key
OPENAI_BASE_URL=https://your-gateway.example.com/v1     # 用网关时改这行
OPENAI_DEFAULT_MODEL=gpt-4o-mini                        # 用网关时改成它支持的模型
```

**做法二：在入口脚本里加载（需要装 python-dotenv）**

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
uv pip install python-dotenv
```

`load_dotenv()` 必须在 import `agents` 之前，否则惰性解析读到的还是空值：

```python
from dotenv import load_dotenv

load_dotenv()  # 必须在 import agents、任何模型调用之前

from agents import Agent, Runner  # noqa: E402
```

### 追踪单独配置

默认追踪导出复用模型调用的那把 key。网关 key 通常不能用于 OpenAI 追踪，你有两种选择。

**简单做法**：本地开发直接关掉，就是路线二里的 `set_tracing_disabled(True)`。

**保留追踪**：让模型和追踪用不同 key。下面是一份**完整可运行的脚本**，和 `gateway_hello.py` 放在同一个目录（`openai-agents-python/` 根目录），命名为 `gateway_with_tracing.py`：

```python
from agents import (
    Agent,
    Runner,
    set_default_openai_api,
    set_default_openai_client,
    set_tracing_export_api_key,
)
from openai import AsyncOpenAI

# 1. 端点 + 网关 key；use_for_tracing=False 表示这把 key 不用于追踪
client = AsyncOpenAI(
    base_url="https://your-gateway.example.com/v1",
    api_key="gateway-key",
)
set_default_openai_client(client, use_for_tracing=False)

# 2. 追踪 key 单独给，发往 OpenAI 官方
set_tracing_export_api_key("sk-tracing-key")

# 3. 网关通常只支持 Chat Completions
set_default_openai_api("chat_completions")


async def main():
    # 4. 模型名换成网关真正支持的
    agent = Agent(
        name="Assistant",
        instructions="You only respond in haikus.",
        model="gpt-4o-mini",
    )
    result = await Runner.run(agent, "Tell me about recursion in programming.")
    print(result.final_output)


if __name__ == "__main__":
    import asyncio

    asyncio.run(main())
```

运行它：

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
python gateway_with_tracing.py
```

它和 `gateway_hello.py` 的差别只在追踪那两行：这一个保留追踪、单独指定 key，另一个直接关掉。四项运行时配置完全一样，所以改占位符的方法也一样。

不用自定义 client 时，同样的思路写成 `set_default_openai_key(key, use_for_tracing=False)`，再单独设追踪 key。

### 从密钥管理服务读 key

如果你的 key 来自保险库、需要在进程里动态切换，用设置函数代替环境变量。**下面是代码片段而不是完整脚本**——端点用 `OPENAI_BASE_URL` 环境变量给，再把这段嵌进你的入口脚本，位置在任何模型调用之前：

```python
from agents import set_default_openai_key

set_default_openai_key("sk-...")  # 必须在任何模型调用之前
```

它默认 `use_for_tracing=True`，也就是这把 key 同时用于追踪。要拆开就传 `use_for_tracing=False`，再单独设追踪 key。

### 配置项速查

| 你想改什么 | 环境变量 | 对应的函数 / 参数 |
| --- | --- | --- |
| 密钥 | `OPENAI_API_KEY` | `set_default_openai_key()` |
| 端点 | `OPENAI_BASE_URL` | `AsyncOpenAI(base_url=...)` |
| websocket 端点 | `OPENAI_WEBSOCKET_BASE_URL` | — |
| 模型名 | `OPENAI_DEFAULT_MODEL` | `Agent(model=...)` |
| API 形态 | — | `set_default_openai_api()` |
| 追踪密钥 | — | `set_tracing_export_api_key()` |
| 关闭追踪 | — | `set_tracing_disabled()` |

最后再强调一次两条铁律：

1. 所有配置都必须在**第一次模型调用之前**生效。
2. **传了自定义 client，client 就是唯一真相**；没传 client，SDK 才分别读环境变量和设置函数，再把它们组合。

按这两条判断，就不会出现"地址设了、key 却不知道往哪放"的问题。

## 七、第 5 步：跑通 hello_world

四项配置都齐了，现在跑最小示例。**按你上一节走的路线选命令**，别混用：

| 你走的路线 | 跑哪个文件 | 命令 |
| --- | --- | --- |
| 路线一（官方 OpenAI） | 仓库自带示例 | `python examples/basic/hello_world.py` |
| 路线二（兼容网关） | 你自己存的脚本 | `python gateway_hello.py` |

路线二必须跑 `gateway_hello.py`——仓库自带的 `hello_world.py` 里没有网关配置，直接跑会连到官方地址。若你按后面「追踪单独配置」存了 `gateway_with_tracing.py`，这里改成跑那个文件即可，两者验收标准相同。

先看官方示例长什么样（`repo/examples/basic/hello_world.py`）：

```python
import asyncio

from agents import Agent, Runner


async def main():
    agent = Agent(
        name="Assistant",
        instructions="You only respond in haikus.",
    )

    result = await Runner.run(agent, "Tell me about recursion in programming.")
    print(result.final_output)
    # Function calls itself,
    # Looping in smaller pieces,
    # Endless by design.


if __name__ == "__main__":
    asyncio.run(main())
```

路线一在 SDK 根目录下运行它：

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
python examples/basic/hello_world.py
```

路线二则运行上一节存下的脚本：

```bash
# 工作目录：openai-agents-python/（SDK 根目录）
python gateway_hello.py
```

预期输出是一首三行俳句，内容每次不同但形状固定：

```text
Function calls itself,
Looping in smaller pieces,
Endless by design.
```

看到俳句，说明"环境 + key + 网络"三件事同时通了。这一步是整章的验收点——没跑通就先去下面的"常见坑"对照，别急着往下读。

这段代码里的三行值得单独看一眼，它们对应后文的核心概念：

| 代码行 | 此刻做了什么 |
| --- | --- |
| `Agent(...)` | 纯声明，不发请求。它只定义了"指令"和默认模型。 |
| `Runner.run(agent, "...")` | 这里才发生模型调用、轮次计数、停止判定（第 4 章）。 |
| `print(result.final_output)` | `final_output` 的类型由 `output_type` 决定，默认是 `str`（第 5 章）。 |

### examples/ 的 17 个目录，按用途分四组

初学者最容易犯的错，是把 `examples/` 当目录挨个浏览。它们有明确的功能分层：

| 组 | 目录 | 你会看到什么 |
| --- | --- | --- |
| 基础动作 | `basic/` | `hello_world`、`tools`、`stream_text`、`usage_tracking`、`tool_guardrails`、`retry` 等 |
| 编排范式 | `agent_patterns/`、`handoffs/` | `routing`（分诊）、`agents_as_tools`、`parallelization`、`human_in_the_loop` 等 |

`tests/` 的目录名基本对应源码模块。所以"想知道某个模块的边界行为"最省力的路径，就是直接进同名测试目录。

## 常见坑与排查

按症状查，每条都给出"症状 → 原因 → 修法"。

1. **`pip install` 成功，运行却 `ModuleNotFoundError: No module named 'agents'`。**
   原因：装到了另一个解释器（系统 Python vs 虚拟环境），或在错误的终端会话里。
   修法：跑第八节那条自查命令看清解释器路径，然后统一用 `uv run python ...`。

2. **Python 3.9 下 import 就报语法/类型错误。**
   原因：`requires-python = ">=3.10"`，源码大量使用 `X | None` 与 `kw_only` dataclass 字段。
   修法：升级到 3.11 或 3.12。

3. **模型调用超时、`APIConnectionError`，但浏览器能打开网页。**
   原因：企业代理没传给 Python 进程，或 `OPENAI_BASE_URL` 指向了不可达网关。
   修法：设 `HTTPS_PROXY`/`HTTP_PROXY`；确认 `OPENAI_BASE_URL` 以 `/v1` 结尾；离线时用 `set_tracing_disabled(True)` 关掉追踪导出，减少噪音。

4. **报 `model not found` 或"模型不存在"，但 key 和地址都确认过没错。**
   原因：沿用了 SDK 默认模型 `gpt-5.6-luna`，网关并不提供它。
   修法：用 `Agent(model="...")` 或 `OPENAI_DEFAULT_MODEL` 设成网关控制台里真实的模型 ID，照原样抄。

5. **报 404 或"接口不支持"，连的是自建网关。**
   原因：SDK 默认走 Responses API，而多数兼容网关只实现了 Chat Completions。
   修法：在任何模型调用前执行 `set_default_openai_api("chat_completions")`。

6. **只看到一条 warning：`OPENAI_API_KEY is not set, skipping trace export`。**
   原因：追踪导出需要 key（默认与模型调用同一把），这只影响 trace 上传，不影响运行。
   修法：补 key，或 `set_tracing_disabled(True)`，或用 `set_tracing_export_api_key(...)` 单独指定。

7. **传 `http_client=` 给 `AsyncOpenAI` 后类型不匹配或连接异常。**
   原因：0.25 依赖 `openai>=3`，默认走 HTTPX2，旧教程里的 `httpx` 客户端不再适用。
   修法：按 `repo/docs/config.md` 用 `httpx2` 与 `DefaultAsyncHttpx2Client` 构造。

8. **Windows 上 `.venv\Scripts\activate` 提示"禁止运行脚本"。**
   原因：PowerShell 执行策略限制，不是 SDK 问题。
   修法：只对当前会话放宽（`Set-ExecutionPolicy -Scope Process RemoteSigned`），或干脆全程用 `uv run`。

9. **clone 仓库时连接被重置或超时。**
   原因：所在网络访问 github.com 受限。
   修法：配置代理后重试；或用 GitHub 镜像加速；或从 Releases 页下载源码压缩包。拿到源码后，后续步骤完全一样。

## 本章小结

- 本机目录是 `openai-agents-python/`；课程里的 `repo/xxx` 是逻辑前缀，点击跳 GitHub，不用真的建 `repo` 目录。
- 环境三步：装 Python 3.12 → 装 uv → clone 源码后用 `uv venv` + `uv pip install -e .`。
- 版本硬约束：`requires-python>=3.10`、`openai>=3`、`pydantic>=2.12`；0.25 的 HTTP 客户端用 httpx2。
- 官方场景只需 `OPENAI_API_KEY`；网关场景还要配 base URL、模型名、API 形态，四项缺一不可。
- 配置惰性解析、须在首次调用前生效；SDK 不自动读 `.env`，可用 `uv run --env-file` 或 `python-dotenv`。
- 传了自定义 client 后，client 的 `base_url` 与 `api_key` 覆盖一切环境变量和设置函数。
- `hello_world` 验证环境，`run_demo_loop` 验证行为；两者都不能当回归测试用。
- 环境出事先跑自查命令；阅读顺序是示例 → 文档 → 源码，源码从门面层进。
